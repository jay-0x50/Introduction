대표 프로젝트

Exception

Unreal Engine 5 기반 보스 레이드 액션 RPG

플레이어 Hendel이 무너진 Runtime의 보스들을 상대하는 액션 RPG 데모입니다. 보스 패턴을 보고 회피와 패링으로 틈을 만든 뒤, Groggy를 쌓아 처형하는 전투 흐름을 제작하고 있습니다.

구현한 기능

  • 약공격, 강공격, 회피, 패링, 락온, 처형을 전투 상태로 나눠 구현했습니다.
  • 보스의 HP, Groggy, 페이즈 전환과 듀얼 보스의 공격 순서를 관리했습니다.
  • 체크포인트 자동 저장, 사망 후 리스폰, Continue 로드 흐름을 연결했습니다.
  • 플레이어와 보스 수치가 바뀔 때 Delegate로 HUD를 갱신했습니다.

현재 결과

필드에서 체크포인트를 거쳐 보스전에 진입하고, 패배하면 저장 지점에서 다시 도전할 수 있습니다. 전투 규칙은 C++에 두고 Blueprint는 UI 배치, 애니메이션, VFX와 사운드 연결에 사용했습니다.

근접 공격이 눈에 보이는 범위와 어긋나는 문제

해결: 선 하나로 검사하는 대신 캐릭터 전방을 Sphere Sweep으로 조회했습니다. 한 공격에서 적중한 대상은 TSet에 기록해 같은 대상에 데미지가 반복 적용되지 않도록 처리했습니다.

전투 로직과 HUD가 서로 직접 참조하는 문제

해결: HP, Stamina, Groggy가 바뀌는 시점에 Delegate를 Broadcast하고 HUD가 이벤트를 받도록 바꿨습니다. UI는 값을 표시하고 전투 규칙은 계산하지 않도록 역할을 나눴습니다.

전투, 저장, UI의 책임을 나눠 기능을 추가할 때 수정 범위를 줄였습니다.

리듬 게임

PyMax

노트 데이터와 입력 시간을 직접 다루는 4키 리듬 게임

곡을 선택하면 노트 파일을 읽어 화면에 배치하고, Q·W·O·P 입력 시간에 따라 판정을 계산합니다. 콤보, 점수, 피버 게이지와 결과 화면까지 한 프로그램 안에서 구현했습니다.

구현한 기능

  • 텍스트 기반 노트 데이터를 읽어 레인별 노트와 시작 시간을 구성했습니다.
  • 입력 시점에 따라 판정을 나누고 콤보, 점수, 피버 게이지에 반영했습니다.
  • 곡 선택부터 플레이, 결과 확인까지 리듬 게임의 기본 화면 흐름을 만들었습니다.

문제와 해결

문제: 화면 프레임에 기대어 시간을 계산하면 음악과 노트의 판정 시점이 어긋났습니다.

해결: 곡이 시작된 시각을 저장하고 매 프레임 시스템 시간과의 차이를 계산해 노트 위치와 판정에 사용했습니다.

결과: 음악 재생과 입력 판정이 같은 시간 기준을 사용하도록 정리했습니다.

화면 결과와 실제 Python 소스에서 확인되는 기능만 정리했습니다.

DirectX 슈팅

SpaceOut

외부 게임 엔진 없이 만든 2D 슈팅 게임

플레이어가 적의 투사체를 피하면서 반격하는 슈팅 게임입니다. DirectX 11로 화면을 그리고, 이동과 탄환 업데이트, 적 충돌과 점수 처리를 게임 루프 안에서 직접 다뤘습니다.

구현한 기능

  • DirectX 11 렌더링 흐름과 스프라이트 출력을 구성했습니다.
  • 플레이어 이동, 적 패턴, 탄환과 충돌, 점수 처리를 연결했습니다.
  • 타이틀, 게임 시작, 플레이와 점수 화면을 구현했습니다.

문제와 해결

문제: 투사체가 늘어날수록 생성과 충돌 검사를 매번 처리해야 했습니다.

해결: 충돌은 AABB 범위로 검사하고, 탄환은 미리 만든 목록에서 사용 여부를 바꿔 다시 쓰도록 구성했습니다.

결과: 렌더링과 게임 규칙을 직접 연결하며 엔진이 처리하던 단계를 코드로 확인했습니다.

팀 프로젝트

Magic Girl Kawaii Lovelies

음성 명령으로 보스 패턴을 푸는 팀 게임

플레이어가 보스 패턴을 피하다가 정해진 상황에 음성 명령을 사용해 전투 흐름을 바꾸는 프로젝트입니다. 메인 프로그래머로 보스 로직과 서버 응답을 게임 이벤트로 연결했습니다.

구현한 기능

  • 보스의 대기, 추적, 공격, 그로기와 페이즈 전환 상태를 나눴습니다.
  • 마이크 입력과 서버 응답을 받아 전투 중 특정 패턴을 푸는 이벤트로 바꿨습니다.
  • 공용 전투 로직과 팀원의 작업 범위를 나눠 기능을 합쳤습니다.

문제와 해결

문제: 음성 인식 결과가 늦게 도착하면 보스가 판정하는 시점과 어긋났습니다.

해결: 보스 상태에 음성 입력을 기다리는 구간을 두고, 도착한 결과를 다음 처리 시점에 읽도록 흐름을 나눴습니다.

결과: 음성 입력, 보스 상태와 화면 반응이 한 전투 규칙 안에서 이어지도록 만들었습니다.
