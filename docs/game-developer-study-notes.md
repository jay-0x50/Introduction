# 게임 클라이언트 개발 공부와 포트폴리오 준비 노트

정리일: 2026-09-22

위키독스의 「게임 프로그래머 로드맵」에서 현재 준비에 필요한 장을 골라 요약했습니다.
원문 요약과 박재영의 프로젝트에 적용할 연습을 구분했습니다. 체크박스는 앞으로 확인할 항목이며, 완료한 경력이나 성과를 뜻하지 않습니다.
원문은 퇴고 중이며 Unreal 장에는 저자의 검증 필요 표시가 있습니다. 학습 순서의 참고로 읽고 엔진 동작은 사용 버전에 맞는 공식 문서로 확인합니다.

- 원문은 핵심을 담은 2~3분 시연 영상을 제안합니다. 영상 길이 자체보다 판단에 필요한 장면을 담는 것이 목적입니다.

### Exception

- [ ] 공격 한 번의 시작과 끝, 적중 이력 초기화 위치를 그림 한 장으로 설명합니다.
- [ ] 동일 대상의 여러 충돌 결과와 실제 피해 적용 횟수를 구분해서 확인합니다.
- [ ] 처형 중 Groggy 회복이 호출될 때 어떤 상태를 유지하는지 시연합니다.
- [ ] HUD에 전달되는 이벤트와 최초 수치 표시 시점을 구분합니다.
- [ ] 저장에 포함되는 진행 정보와 재시작 시 복구되는 값을 표로 적습니다.

### PyMax

2026-09-22에 설명한 실제 경험: 곡 재진입 시 로딩 대기는 남는데 음악·영상이 먼저 재생되어, 리소스 로딩 완료를 재생 시작 조건으로 변경했습니다. 이 회고는 [경험 근거](./portfolio-evidence.md)에 기록했습니다.

- [ ] 최초 진입과 재진입에서 로딩 상태·화면 전환·재생 시작 조건이 어떻게 달랐는지 설명합니다.
- [ ] 노트의 목표 시각·현재 시각·속도가 위치에 미치는 영향을 계산합니다.
- [ ] BPM이 달라지면 판정 범위가 어떻게 달라지는지 확인합니다.
- [ ] 입력 판정 뒤 콤보·점수·피버 게이지가 갱신되는 장면을 연결합니다.
- [ ] 오디오 지연을 측정하지 않았다면 완벽한 동기화나 개선 수치를 주장하지 않습니다.

### SpaceOut

- [ ] 학원 예제에서 배운 구조와 직접 수정한 범위를 나누어 표시합니다.
- [ ] 두 사각형의 변이 닿기만 할 때 충돌로 처리하는지 설명합니다.
- [ ] 화면 밖 비트맵에 그린 뒤 창에 복사하는 과정을 도식화합니다.
- [ ] 탄환 생성과 제거 위치를 확인합니다. DirectX나 풀링 구현으로 표현하지 않습니다.

### Error Dungeon

- [ ] 콤보 입력을 예약할 수 있는 구간과 실제 다음 공격의 시작 조건을 설명합니다.
- [ ] 사망 뒤 재화 드랍·이동·회복·적 초기화가 진행되는 순서를 시연합니다.
- [ ] 처치한 보스와 일반 적의 복구 규칙을 구분합니다.
- [ ] WebGL 실행 결과와 기록 API 연결을 각각 확인합니다. 기록 API를 전투 서버 검증으로 설명하지 않습니다.

## 10. 남은 기간의 준비 순서

다음 순서는 진학 제출을 먼저 준비하고 취업 자료를 함께 관리하기 위한 개인 작업 제안입니다.

1. **제출 자료 확정:** 진학 PDF에서 작품 화면, 담당 기능, 배운 점을 먼저 읽히게 합니다.
2. **대표 장면 선별:** Exception에서 전투·보스·HUD·체크포인트 장면을 고르고 짧은 캡션을 붙입니다.
3. **문제 해결 근거 확보:** 재현 조건과 확인한 원인이 있는 사례를 골라 전후 동작을 기록합니다.
4. **보조 작품 정리:** PyMax·Error Dungeon의 차별점을 압축하고 SpaceOut은 기초 실습으로 표시합니다.
5. **기본기 보완:** 자료구조·객체 수명·상태 전환 등 현재 코드의 설명이 막히는 개념을 공부합니다.
6. **면접 말하기:** 화면을 보며 1분 작품 소개와 3분 구현 설명을 녹음하고 불명확한 부분을 고칩니다.
7. **제출 점검:** 진학용 PDF의 잘림과 글자 크기, 취업용 사이트의 이력서 연결, GitHub 실행 안내를 확인합니다.

## 11. 문제 해결 기록 양식

과거 오류가 실제로 있었는지 확실하지 않으면 구현 의도나 앞으로의 검증 항목으로 적습니다.

```text
기능과 상황:
예상한 동작 / 관찰한 동작:
재현 조건:
확인한 로그·변수·호출 순서:
원인과 근거:
선택한 수정 / 다른 대안:
수정 뒤 확인한 장면:
남은 한계 / 다음 확인:
관련 화면·영상·커밋:
```

결과는 실제 확인한 동작으로 적습니다. FPS·지연·오류율 같은 수치는 동일한 조건으로 측정한 기록이 있을 때만 사용합니다.
GitHub 공개, 포트폴리오 웹사이트 배포, 게임 빌드 배포는 각각 구분해 기록합니다.
