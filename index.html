자기소개서

플레이하면서 문제를 찾고, 코드로 고칩니다.

입력과 판정, 전투 상태와 UI가 실제 플레이에서 어떻게 느껴지는지 확인하며 개발해 왔습니다.

지원 동기

초등학교 3학년 때 스크래치로 처음 프로그래밍을 접했고, 중학교에서는 오렌지보드로 자동 손 소독제를 만들어 학급에 기부했습니다. 코드가 실제 장치의 동작으로 이어지고 누군가에게 쓰이는 경험을 하면서, 직접 만든 기능이 사용자에게 전달되는 과정에 흥미를 느꼈습니다.

게임을 플레이할 때도 타격 판정은 어디에서 시작되는지, UI는 어떤 값에 반응하는지 궁금해합니다. 궁금한 기능은 작은 형태로 구현해 보고, 직접 플레이하며 어색한 입력과 피드백을 고치는 과정에서 게임플레이 프로그래밍을 진로로 정했습니다.

프로젝트 경험

Exception에서는 플레이어 전투, 보스 HP와 Groggy, 체크포인트 저장, HUD 갱신을 C++로 구현했습니다. 근접 공격은 Sphere Sweep으로 판정하고 공격별 피격 대상을 관리했으며, 수치 변화는 Delegate를 통해 HUD에 전달해 전투 로직과 화면 표시를 분리했습니다.

PyMax에서는 노트 생성부터 4키 입력 판정, 콤보와 점수 계산까지 구현하고 음악과 노트의 싱크를 시스템 시간 기준으로 맞췄습니다. SpaceOut에서는 DirectX 11로 렌더링과 충돌 처리를 직접 구성했습니다. 6인 팀 프로젝트에서는 보스 로직과 음성 입력 연동을 맡아 여러 기능을 하나의 전투 흐름으로 연결했습니다.

강점 & 협업

CodeUs 동아리 부장과 6인 팀 프로젝트의 메인 프로그래머를 맡으며, 제 기능을 끝내는 데서 멈추지 않고 팀원의 오류를 함께 재현했습니다. 공용 로직이 겹칠 때는 작업 범위를 다시 나누고, 음성 인식 서버 응답과 보스 상태, UI 반응이 같은 흐름에서 동작하도록 연결했습니다.

교내에 게임을 배포한 뒤에는 플레이 피드백을 직접 모아 조작과 진행 흐름을 수정했습니다. 코드 리뷰와 디버깅도 완성된 결과를 평가하는 일이 아니라, 문제의 원인과 설계 방향을 팀이 함께 맞추는 과정이라고 생각합니다.

입사 후 포부

새로운 코드베이스에서는 먼저 실행 흐름과 수정 범위를 이해하고, 맡은 기능을 작은 단위로 구현해 직접 플레이하며 검증하겠습니다. 수정 이유와 영향을 팀원이 이어서 파악할 수 있도록 구조와 의도를 분명하게 남기겠습니다.

초기에는 팀의 코드 작성 방식과 게임의 플레이 루프를 빠르게 익히고, 이후에는 실제 플레이에서 발견한 문제를 바탕으로 전투·보스·상호작용 구조를 제안할 수 있는 게임플레이 프로그래머로 성장하겠습니다.
